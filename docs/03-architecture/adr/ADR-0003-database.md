# ADR-0003: PostgreSQL и модель доступа к данным

## Статус
Accepted

## Решение

PostgreSQL является канонической транзакционной БД TourCRM.

SQLAlchemy используется как application data-access layer, Alembic — как механизм schema migrations.

Логическая модель, описанная в `docs/03-architecture/data-model.md` и `docs/03-architecture/database-schema.md`, является источником требований к физической схеме.

## Принципы

- данные с исторической ценностью не уничтожаются без документированного правила;
- foreign keys и database constraints используются для защиты целостности;
- бизнес-инварианты, которые невозможно выразить constraint'ами, проверяются application/domain layer;
- миграции версионируются и являются частью репозитория;
- schema changes должны быть обратимыми или сопровождаться документированным rollback/forward-fix планом;
- production schema не изменяется вручную.

## Почему PostgreSQL

Реляционная модель хорошо соответствует связям между людьми, членством, мероприятиями, участием, походами, финансами, документами и аудитом. PostgreSQL также даёт развитые индексы, ограничения и транзакционную семантику.

## Альтернативы

NoSQL-only storage отклонён для основной БД: он увеличивает сложность поддержания реляционных инвариантов домена.

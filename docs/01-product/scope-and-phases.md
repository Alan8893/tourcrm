# TourCRM — Scope and Phases

## 1. Общий принцип

Архитектура TourCRM должна предусматривать полный целевой набор функций, но реализация выполняется итеративно. Наличие домена в архитектуре не означает обязательную реализацию в MVP.

## 2. MVP — ядро системы

### Identity & Access

- регистрация;
- вход и выход;
- восстановление доступа;
- подтверждение регистрации администратором;
- приглашение по ссылке/коду;
- импорт участников;
- роли и permissions;
- профиль пользователя;
- базовый аудит безопасности.

### Club CRM

- клуб;
- физические лица;
- участники;
- инструкторы;
- родители/законные представители;
- связи родитель ↔ ребёнок;
- членство в клубе;
- учебные группы;
- статусы и история членства.

### Calendar & Events

- единая сущность Event;
- типы мероприятий;
- расписание;
- повторяющиеся занятия;
- участники мероприятия;
- инструкторы/руководители;
- посещаемость;
- причины отсутствия;
- отмена/перенос;
- базовые уведомления.

### Platform Foundation

- адаптивный web UI;
- REST API;
- PostgreSQL;
- миграции;
- файловая абстракция;
- конфигурация окружений;
- Docker;
- CI/CD;
- логирование;
- health checks;
- резервное копирование инфраструктурного уровня.

## 8. Integration Phase — Турслёты

Существующий сайт турслётов подключается после анализа предоставленного архива.

Целевой вариант:

`TourCRM ↔ Integration API ↔ TourSlet`

Возможные функции:

- единая или связанная идентификация пользователей;
- передача участников;
- регистрация на турслёт;
- результаты;
- места;
- награды;
- импорт результата в профиль участника;
- ссылочная связь с мероприятием.

Конкретный вариант (отдельный сервис / модуль / SSO / API) фиксируется после технического анализа архива турслётов.

## 9. Out of Scope для MVP

Следующие функции могут быть описаны заранее, но не блокируют MVP:

- отдельное мобильное приложение;
- сложный чат;
- полноценный бухгалтерский учёт;
- сложная система платежей/эквайринга;
- SSO с турслётами;
- автоматические юридические workflows;
- расширенный рейтинг;
- продвинутая аналитика;
- внешние календарные интеграции.

## 10. Правило изменения scope

Добавление функции в MVP допускается только через обновление scope-документа и соответствующей Issue. Нельзя превращать MVP в набор постоянно растущих незапланированных требований.

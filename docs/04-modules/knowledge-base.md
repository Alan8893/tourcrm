# TourCRM — База знаний

## 1. Назначение

База знаний — встроенный модуль хранения и публикации учебных, методических, организационных и справочных материалов туристского клуба.

Она должна быть полезна как участникам и родителям, так и инструкторам и администраторам.

## 2. Принципы

1. Контент имеет жизненный цикл draft → review → published → archived.
2. История опубликованных версий сохраняется.
3. Права на чтение и редактирование определяются отдельно.
4. Вложенные файлы проходят через общий File/Document Storage контур.
5. Статья не должна содержать критически важные данные только в свободном тексте, если они используются бизнес-логикой.

## 3. KnowledgeArticle

Ключевые поля:

- id;
- club_id;
- category_id;
- title;
- slug;
- summary;
- content;
- status;
- author_person_id;
- created_at;
- updated_at;
- published_at;
- archived_at.

## 4. Версии

`KnowledgeArticleVersion` хранит:

- article_id;
- version_number;
- content;
- editor;
- created_at;
- change_summary.

Публикация создаёт неизменяемую версию. Редактирование опубликованной статьи создаёт новый draft/version, а не переписывает историю.

## 5. Категории и теги

Категории должны быть справочником. Теги позволяют cross-domain поиск.

Примеры категорий:

- туризм;
- первая помощь;
- ориентирование;
- узлы;
- снаряжение;
- безопасность;
- документы клуба;
- подготовка к походу;
- правила поведения;
- материалы для инструкторов.

## 6. Связи

Статья может быть связана с:

- Event;
- Trip;
- Skill;
- Achievement;
- Equipment;
- Document;
- другими статьями.

Это позволяет, например, из занятия перейти к нужной статье базы знаний.

## 7. Поиск

Нужен полнотекстовый поиск по:

- title;
- summary;
- published content;
- tags.

Для первого этапа допускается PostgreSQL full-text search. Отдельный поисковый движок не является обязательным.

## 8. Медиа

Поддерживаются изображения, PDF и другие документированные форматы. Хранение реализуется через общий storage слой, а не в самой сущности статьи.

## 9. Права доступа

Участники и родители: опубликованный контент.

Инструкторы: опубликованный и разрешённый внутренний контент, а также создание/редактирование материалов при наличии permission.

Администраторы: полный контентный доступ.

## 10. Аудит

Аудируются:

- создание статьи;
- изменение;
- публикация;
- архивирование;
- изменение категорий/тегов;
- управление правами;
- удаление/архивирование вложений.

## 11. Feature setting

`knowledge_base.enabled`.

Отключение модуля не удаляет опубликованный контент.

## 12. Приёмочные критерии

- можно создать draft статьи;
- draft не виден обычной аудитории;
- опубликованная версия доступна разрешённым пользователям;
- изменение опубликованной статьи сохраняет прошлую версию;
- работает поиск и фильтрация;
- статья может быть связана с другими доменными объектами;
- файлы проходят через общий storage;
- права проверяются на API.

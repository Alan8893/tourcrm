# TourCRM — Achievements, Skills, Qualifications and Rating

## 1. Назначение

Документ определяет правила для туристских достижений, навыков, квалификаций и рейтинга участников клуба.

Документ не заменяет первичные факты. Источниками фактов остаются мероприятия, посещаемость, походы, результаты соревнований и подтверждённые документы.

Производные показатели должны быть вычисляемыми и пересчитываемыми.

## 2. Доменные объекты

### 2.1 Achievement

Шаблон достижения, существующий в справочнике клуба.

Обязательные свойства:

- id;
- club_id;
- code;
- name;
- description;
- category;
- icon/media reference, если используется;
- award_mode: `manual` | `automatic` | `both`;
- status;
- created_at;
- updated_at.

`code` уникален в пределах клуба.

### 2.2 AchievementRule

Правило автоматического получения достижения.

Правило должно быть версионируемым и иметь:

- id;
- achievement_id;
- version;
- status;
- condition definition;
- effective_from;
- effective_to;
- created_by;
- created_at.

Правила не должны храниться только как произвольный исполняемый код из БД. Предпочтительно использовать декларативную модель условий, которую backend валидирует.

### 2.3 AchievementAward

Факт выдачи достижения конкретному Person.

Содержит:

- id;
- achievement_id;
- person_id;
- awarded_at;
- award_mode;
- rule_version, если автоматическое;
- awarded_by, если ручное;
- source_type;
- source_id;
- note;
- revoked_at;
- revoke_reason.

История выдачи не должна уничтожаться физическим удалением.

### 2.4 Skill

Справочник туристских навыков.

Примеры:

- ориентирование;
- вязка узлов;
- первая помощь;
- установка палатки;
- работа с плавсредством;
- безопасность на маршруте.

Skill содержит:

- id;
- club_id;
- code;
- name;
- description;
- category;
- status.

### 2.5 PersonSkill

Состояние навыка конкретного Person.

Рекомендуемые уровни:

`unknown` → `learning` → `practiced` → `verified` → `mentor`.

Содержит:

- person_id;
- skill_id;
- level;
- verified_at;
- verified_by;
- source_type/source_id;
- notes;
- updated_at.

Уровень не должен повышаться только на основании самозаявления, если для уровня предусмотрено подтверждение инструктором.

### 2.6 Qualification

Формализованная квалификация, разряд, сертификат или иной подтверждённый уровень.

Содержит:

- id;
- person_id;
- qualification_type;
- number/code при наличии;
- issued_by;
- issued_at;
- valid_from;
- valid_to;
- status;
- document_id;
- notes.

Квалификация может быть бессрочной либо иметь срок действия.

## 3. Источники достижений

Достижение может ссылаться на источник факта:

- Event;
- Trip;
- TripParticipant;
- Competition result;
- Qualification;
- verified Skill;
- manual administrative decision.

Ссылка на источник нужна для объяснимости.

Пользователь и инструктор должны иметь возможность понять, почему достижение было назначено.

## 4. Автоматические достижения

Автоматическое достижение должно рассчитываться на основании фактов.

Примеры декларативных условий:

- первый завершённый поход;
- не менее N завершённых походов;
- не менее N километров;
- участие в мероприятии определённого типа;
- определённый результат соревнования;
- подтверждение навыка;
- комбинация нескольких условий.

Система должна предотвращать бесконтрольное повторное начисление одного и того же достижения.

Если достижение допускает многократную выдачу, это должно быть явным свойством Achievement.

## 5. Пересчёт

Производные достижения и статистика должны поддерживать пересчёт.

Пересчёт может потребоваться после:

- исправления результатов похода;
- отмены участия;
- изменения статуса мероприятия;
- изменения правила достижения;
- удаления/отзыва подтверждения.

Ручное достижение не должно исчезать из истории из-за обычного пересчёта автоматических правил.

## 6. Рейтинг

Рейтинг является производной функциональностью и может быть отключён через системную настройку.

Feature setting:

`rating.enabled`.

Выключение рейтинга не должно удалять исторические данные достижений и результаты.

### 6.1 Принципы

Рейтинг не должен быть первичным источником истины.

Рейтинг рассчитывается из документированных показателей.

Формула должна иметь версию.

Пример потенциальных факторов:

- завершённые мероприятия;
- походный опыт;
- километраж;
- достижения;
- результаты соревнований;
- подтверждённые навыки;
- посещаемость.

Конкретные веса и формула являются отдельным бизнес-решением и до их утверждения не должны быть зашиты в код.

### 6.2 Периоды рейтинга

Поддерживаются как минимум:

- текущий рейтинг;
- рейтинг за период;
- исторический рейтинг.

Период должен быть явно определён часовым поясом клуба.

### 6.3 Ограничения

Рейтинг не должен автоматически использовать чувствительные персональные или медицинские данные.

Рейтинг участника и внутренняя служебная аналитика могут иметь разные уровни видимости.

## 7. Настройки приватности

Для достижений и рейтинга должны существовать настройки видимости.

Минимальные уровни:

- private;
- club_staff;
- club_members;
- public, только если такая возможность отдельно включена политикой клуба.

Для несовершеннолетних публичная публикация должна быть отключена по умолчанию.

## 8. UI-сценарии

### 8.1 Карточка участника

Показывает:

- достижения;
- навыки;
- квалификации;
- статистику;
- при включённом рейтинге — позицию и период.

### 8.2 Каталог достижений

Администратор может:

- создать достижение;
- редактировать описание;
- включить/отключить его;
- настроить способ получения;
- просмотреть правила.

### 8.3 Выдача вручную

Уполномоченный инструктор/администратор:

1. выбирает участника;
2. выбирает достижение;
3. указывает основание;
4. при необходимости добавляет документ или ссылку на источник;
5. подтверждает выдачу.

### 8.4 Подтверждение навыка

Инструктор:

1. открывает навык участника;
2. выбирает новый уровень;
3. указывает основание;
4. сохраняет.

## 9. Права доступа

Участник:

- видит свои достижения/навыки/квалификации в пределах политики видимости;
- не может самостоятельно выдавать себе достижение;
- не может изменять подтверждённую квалификацию.

Родитель:

- видит достижения и квалификации связанных детей в пределах разрешений;
- не изменяет профессиональные подтверждения без специального права.

Инструктор:

- видит участников доступных ему групп;
- может подтверждать навыки при наличии permission;
- может выдавать разрешённые достижения;
- может просматривать статистику своих групп.

Администратор:

- управляет справочниками;
- управляет правилами автоматических достижений;
- управляет рейтингом;
- имеет полный служебный доступ в рамках политики клуба.

## 10. Аудит

Изменения должны попадать в AuditLog:

- создание/изменение достижения;
- изменение правила;
- ручная выдача;
- отзыв достижения;
- подтверждение навыка;
- изменение квалификации;
- изменение формулы рейтинга;
- пересчёт производных показателей.

## 11. Acceptance Criteria

- [ ] Справочник достижений поддерживает manual/automatic/both.
- [ ] Факт выдачи хранится отдельно от шаблона достижения.
- [ ] Автоматические правила версионируются.
- [ ] Есть объяснимый источник получения достижения.
- [ ] Исторические выдачи не теряются при пересчёте.
- [ ] Навык отделён от достижения.
- [ ] Подтверждение навыка содержит автора и источник.
- [ ] Квалификация поддерживает срок действия и документ.
- [ ] Рейтинг можно отключить настройкой.
- [ ] Рейтинг является производным и имеет версию формулы.
- [ ] Права доступа ограничивают просмотр и изменение данных.
- [ ] Для несовершеннолетних публичная публикация отключена по умолчанию.
- [ ] Значимые изменения аудируются.
